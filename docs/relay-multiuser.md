# 给别人中转：能不能做、要多少资源

结论先说：**技术上现在就能给，资源几乎不花；真正的成本是带宽和「每户一条独立通道」的运维，不是 CPU 和内存。**
但**不能直接让多个人共用现在这条链**——现在是单用户模型，一共享，配对令牌就成公共令牌。

## 1. 现在这条链（单用户）

```
手机 → pet.regrevia.com/:80 (Caddy) → 服务器 127.0.0.1:8443 (sshd -R 落点)
     → Mac 上 launchd 的 ssh -N -T -R 8443:127.0.0.1:8443 → Mac 127.0.0.1:8443 TLS 反代
     → 宿主 DSH 的插件 HTTP 服务
```

一台 Mac 一条 `ssh -R`，服务器上占**一个端口 + 一条常驻 TCP**。插件只认**一个**令牌（`tokenStore.current()`），
面板给出的配对链接就是 `?k=<这个令牌>`；带上它的人等于拿到这台 Mac 上的会话读写权。

## 2. 要给别人用，缺的是隔离，不是服务器

| 必须改 | 为什么 | 工作量 |
| --- | --- | --- |
| 每户一个令牌 | 现在全局一个，共享即互相能读会话、能发消息 | 小：`tokenStore` 从单值换成 `owner → token` |
| 每户一个落点端口 | `ssh -R` 只能绑不同端口，Caddy 按路径/子域名分流到各自端口 | 小：加 `-R 8444/8445…` + Caddy 一段 `handle_path` |
| 每户一条隧道 | 对方的 Mac 自己往服务器打洞，我们只做落点，不碰对方机器 | 中：发一个一次性脚本，装 launchd |
| 限流与配额 | 一个入口被刷会拖慢全站 | 中：Caddy `rate_limit` 或按 IP/令牌计数 |
| 备案与合规 | 域名对外提供**服务**（不是个人自用）在国内要走 ICP；现在 443 关着就是因为备案没下来 | 不在代码里 |

## 3. 服务器实际余量（2026-11-03 19:30，`root@42.193.189.240` 实测）

- 2 vCPU，3.7 GB 内存，已用 672 MB（可用 3.05 GB），load average 0.00
- 磁盘 69 GB 用 10%；TCP 208 个句柄、15 条 estab；Caddy + sshd 常驻，空闲几乎不吃 CPU

按「一个人一条 ssh -R」估：**每户约 1–3 MB 内存、0 CPU（无会话时）、1 个端口、1 条长连接**。
这台机器撑**几十户**在内存和句柄上都毫无压力（Caddy 反代每连接几 KB 栈，主要还是内核 socket 缓冲）。

## 4. 真正会吃资源的是带宽，不是算力

- 纯文字对话：一条消息几 KB，一百户同时聊也就几 Mbps 量级，可以忽略。
- **图片才是大头**：手机拍一张 1–2 MB，原样过中转就是 1–2 MB 出网；十个人各发五张，就是几十 MB。
- 国内云主机出网带宽通常是**固定几 Mbps**（轻量/学生机常见 3–6 Mbps，约 0.4–0.75 MB/s 峰值）。
  这条链一旦被人拿来看图，卡的不是 CPU，是**出网带宽被打满，所有人一起变慢**。
- 所以配额要落在**图片**上：客户端先压到 1600px/JPEG q80（约 200–400 KB）再上传，中转侧限单请求体积，
  比事后限流有效得多。

## 5. 建议

1. **给自己用：维持现状**。一条链、一个令牌最省事，也没有备案问题。
2. **给少数朋友试用**：按第 2 节做「每户令牌 + 每户端口 + 一次性安装脚本」，先不开图片或只开压缩图，
   带宽按 5 Mbps 出网算，同时在线别超过 3–5 人发图。
3. **公开当服务**：不是加机器能解决的——要备案、要滥用处置、要存储与日志策略，属于另起一个产品，
   不建议挂在现在这台宠物中转机上。

## 7. 已实现（2026-11-04）

按第 2 节做的第一版，没有走 ssh，也没有按端口分：**每户一条出站 WS + 每户一个密钥**。

### 7.1 服务端（42.193.189.240）

- `/opt/pet-relay/server.mjs`，systemd `pet-relay.service`，监听 `127.0.0.1:8090`。
- `GET /relay/ws?slug=&secret=`：升级成 WebSocket，就是这台电脑的出口；同一 slug 再连会挤掉旧连接（4001）。
- `GET|POST|… /r/<slug>/<原路径>`：拼成 HTTP 帧压给对应的 WS，等插件回帧再回给调用方。
  未知 slug 404，插件没连 503，请求体超 12 MB 413，30 s 没回 502。
- `GET /relay/health`：`{ok,tenants,online[],pending,uptime}`。
- 租户 `{slug,secret,note,createdAt}` 存 `/etc/pet-relay/tenants.json`（0600，写盘 tmp+rename）。
- Caddy `handle /r/*` 与 `handle /relay/*` → `127.0.0.1:8090`，其余仍原样给 `8443`；用 `handle` 不剥前缀，
  所以插件的路径校验看到的是完整 `/r/<slug>/pet-voice/...`。

租户管理（服务器上）：

```bash
node /opt/pet-relay/admin.mjs list
node /opt/pet-relay/admin.mjs add <slug> "备注"   # 打印中转地址与密钥
node /opt/pet-relay/admin.mjs del <slug>         # 换密钥＝先删再加
```

### 7.2 插件侧（这台电脑）

- `relay.mjs`：配置 `~/.dsh/pet-voice/relay.json`（0600），开机按配置连 `ws://42.193.189.240/relay/ws`；
  收到帧在本地 `127.0.0.1:<宿主端口>` 复跑一遍同样的 HTTP 请求（带原 header，去掉逐跳头），
  回帧给服务器。断线 2 s 起、最多 30 s 退避重连；25 s 一次 ping/pong。
- 面板「连上手机」多一项 **我们的中转**：填地址（slug）与密钥 → 保存并连接；选中它才用这条路。
- 地址由插件算：`http://42.193.189.240/r/<slug>/pet-voice/`，配对链接仍是这个地址 + `?k=<令牌>`，
  `publicBase` 里不含令牌（`source: 'relay'`）。没选中转时完全不影响服务器/局域网/域名三种老路。
- 路径门禁不因中转放宽：`allowed()` 复用 `classifyPublicPath`，只放 `/pet-voice/*`；
  `panel/*` 这类本机接口在中转下依旧 403。

### 7.3 实测

- 真插件（非 stub）连上：`connected:true` 在 2.5 s 内，`relay.json` 被写成 0600。
- 公网 `GET http://42.193.189.240/r/regrevia/pet-voice/api/state` → 本地服务的响应原样回来。
- 公网 `/r/regrevia/panel/state` → 403；未知 slug → 404；插件掉线 → 503。
- 老链 `/pet-voice/…` 未改动，已配对的手机照旧。

### 7.4 还没做

- 配额/限速：单请求 12 MB 是硬顶，但没按户计速；图片仍建议先压到 1600px/q80。
- `ws://`：443 没开（备案未过），备案下来换 `wss://` 只改 `relay.json` 的 `wsUrl` 与 Caddy 一行。
- 密钥轮换没有 UI，走 `admin.mjs del` + `add`。
